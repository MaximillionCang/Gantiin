# Receipt extraction contract

Current code: apps/api/src/ai/extraction.mjs, schemas/extraction.mjs and prompts/extraction.mjs. LangChain ChatGoogle uses separate SystemMessage/HumanMessage evidence and withStructuredOutput(method=jsonSchema), with no tools. One shared API key, explicit role model, one maximum transport retry and a 45-second whole-call deadline. No automatic fixture fallback. Missing authorization/configuration fails before model construction.

Raw extraction preserves readable/issues, merchant/date_text (nullable), original source_text, visible currency/currency_source_text, total_sen/total_source_text and items in printed order. Unknown values stay null, not invented. Essential currency, lines and printed total must be readable for downstream validation. The actual printed goods total is used, never cash tender/change.

Each item has id item-N, original description/source_text, nullable quantity/unit_sen/line_sen, line_basis (gross/net/unknown), and separately evidenced item discounts. Shared adjustments preserve kind (tax/discount/other), amount_sen, description/source_text, treatment (add/subtract/included/unknown), scope (receipt/items/unknown), and explicit item_ids for subsets. Included taxes are evidence, not an added cost. Unsupported charges and ambiguous scopes must block financial processing, never disappear or become guessed allocations.

All monetary fields are integer minor units, MYR sen when currency is MYR. Extraction performs no eligibility decisions, recipient selection or payout arithmetic. The server validates arithmetic and scoped allocation before the decider/payment path. Legacy explicit no-adjustment fixture receipts remain compatible. The implemented allocation and supported quantity/adjustment rules are in [net-cost.md](../engineering/net-cost.md).
